# KPI сотрудника: определения

Раздел «KPI» виден только Насте (правила Firebase: коллекция `kpiTracker`). Данные берутся из раздела «Лидогенерация»: лиды (`maxLeads`), напоминания (`maxReminders`) и недельная статистика автоматизации (`weeklyAutomationStats`).

## Период и нормы
- Расчёт ведётся от даты первого рабочего дня. Итоги за прошлый месяц подводятся до 10-го числа (напоминание с 7-го, настраивается).
- Нормы (минимум, план, отлично) для показателей в штуках умножаются на долю отработанных рабочих дней месяца. Проценты не меняются.
- Неполный первый месяц и личные отсутствия (отпуск, больничный) уменьшают нормы пропорционально; бонус пропорционален отработанной части месяца (настройка).
- Праздники компании не уменьшают норму месяца, личные отсутствия уменьшают.

## Показатели
| Показатель | Как считается |
|---|---|
| Средний SLA | Среднее по процессам: неотвеченные на конец дня, не зачёркнутые follow-up, задержка недельного отчёта. Значение не хуже «Отлично» = 95%, «План» = 90%, «Минимум» = 85%, хуже = 0%. |
| Вывод на встречи (проведено) | Уникальные компании со статусом Call done, дата звонка в периоде. Норма растёт со стажем (таблица в настройках): 1–3 месяц 3 / 4 / 5, с 4-го месяца 8 / 10 / 12, с 7-го месяца 12 / 15 / 18 (минимум, план, отлично). |
| Встречи назначено (справочно) | Уникальные компании, у которых встречу назначили в периоде (поле «Назначена»). Не оплачивается. |
| Живой диалог | Среди лидов с ответом в периоде (без Irrelevant, первый ответ не раньше даты старта) доля тех, у кого в периоде пришёл 2-й и следующий ответ. Один лид считается один раз. |
| Компаний в диалоге | Уникальные компании с ответом в периоде (из лидов). Пороги: кнопка «По истории» в настройках считает среднее по последним полным месяцам (минимум = среднее, план +15%, отлично +30%). |
| Контактов добавлено | Сумма недельных значений «Контактов добавлено в автоматизацию (за неделю)» из статистики автоматизации, пропорционально дням. Нормы из регламента на месяц: минимум 1500, план (среднее) 1800, отлично (хорошее) 2700; пересчитываются на отработанные дни. Кнопка «По истории» в настройках может предложить другие пороги по последним 8 неделям. |
| Replied → Interested | Лиды первого ответа в периоде со статусом Interested, Recommendation, Potential call, Call scheduled, Call done к лидам с ответом (без Irrelevant). |
| Wrong ICP | Лиды со статусом Irrelevant к лидам первого ответа в периоде, только ресёрч сотрудника (не «список от Анастасии»). |
| Верные статусы, внесённость | Ручная месячная проверка выборки диалогов из GetSales. |

Процентные показатели при выборке меньше порога (по умолчанию 10) показываются как «мало данных»: без цвета и без выплаты.

## Выплата
Бонус делится между оплачиваемыми показателями по весам (вес 0 = только контроль). «Минимум» даёт 50% доли, «План» 100%, «Отлично» 120% (настраивается). Если доля верных статусов ниже порога, живой диалог и Replied → Interested не засчитываются.

## Follow-up (журнал напоминаний)
Для напоминаний пишется история: создание, выполнение, перенос даты, удаление (мягкое). «Вовремя» считается от исходной даты. Лид без касания дольше 3 рабочих дней и лимит 3 follow-up без ответа настраиваются.

## Фиксация итогов
Кнопка «Итоги месяца подведены» сохраняет снимок цифр, порогов и сумм. Если после этого данные меняются, раздел показывает, что именно изменилось.

## Тесты
`node tests/kpi/unit.test.cjs` (нужен только Node): запускает расчёты из `index.html` на тестовых данных.

## Несколько сотрудников
В разделе «KPI» есть переключатель сотрудников и кнопка «+ Сотрудник». У каждого свой документ в `kpiTracker`: дата старта, пороги, веса, бонус, отпуск, ежедневные проверки, итоги и фиксация месяцев. При добавлении можно скопировать пороги и веса у другого сотрудника. Чтобы цифры разных людей не смешивались, включается счёт по автору (лиды, сообщения и напоминания, внесённые под почтой сотрудника). Напоминание о закрытии месяца приходит по каждому сотруднику, в архив сотрудник уходит без удаления данных.
